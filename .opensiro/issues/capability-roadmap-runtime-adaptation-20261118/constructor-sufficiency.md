**Decision owner:** developer-composed S4 model agent in a first-party reachable formula/role, choosing real supported alternatives under current rights. Mayor retains S3 operational authority; human/operator owns reserved provider/credential/policy rights. S5 not invented.

## 3. Function-specific minimal S4 construction ports

| Proposed port | Precise input / state | Decisive actor, enforcement / return | Native primitive vs missing part |
| --- | --- | --- | --- |
| **A · FutureRuntimeSignal** | Source-linked future provider change, affected models/roles, confidence, expiry and revision | No arbitrary unsupported external signal becomes valid | Existing runtime registry; proposed bounded source/admissibility reader |
| **B · AdaptationOptions** | Versioned choices `retain`, `migrate to compatible approved preset`, `hold` with simulated compatibility/impact and owner | Only permitted alternatives reach actor | Existing config resolver; proposed typed option state |
| **C · DeveloperDecisionPort** | Independently developer-configured autonomous S4 agent receives A+B, returns one choice, reason, principal and state revision | Actor owns prospective selection only; no built-in hardcoded choice masquerading as C | Reuse first-party formula/model/role interface; add function-specific binding and provenance |
| **D · AuthorizedSessionBridge** | Valid decision plus config revision targets **future** bounded role/session settings | Native application checks provider allowlist, authorized role/scope, stale/revoked permissions, active worker leases and S3 current commitments | Existing `gt config`, loader, lifecycle; missing guarded transaction and mapping |
| **E · ObservedReturnReceipt** | Applied/refused decision ID and **actual subsequent** session runtime/outcome/failed launch | Return to Mayor S3 to regulate current operations; no recommendation-only closure | Existing role/session state, Beads and escalation; proposed causal receipt and cross-session return |

**Proposed sufficiency**: A+B+C+D+E together might establish a *first-party developer-composed S4 C path* only after a working supported mode demonstrates a real future distinction, independently chosen option, an authorized changed later session, and returned observable operation/feedback. Mock, generic webhook, status dashboard, research summary, open PR or static policy is insufficient. No current C grade or installed ports are asserted.

**Exclusions:** no new policy engine, unbounded polling, automatic S5 right, mandatory S1/S2/S3/S3* change, non-native framework. S4 future adaptation must differ materially from ordinary current S3 rate-limit failover.
