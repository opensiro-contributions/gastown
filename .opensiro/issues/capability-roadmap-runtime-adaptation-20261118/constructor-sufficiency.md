## 3. Minimal complete S4 first-party C construction

**Required property:** A first-party, function-specific path lets the developer compose a lawful autonomous future adaptation decider, with real effect on subsequent Gas Town work and returned feedback; static notifications or role settings alone are insufficient.

**Physical interface count is NOT prescribed.** Reuse as many existing Gas Town mechanisms as possible; do not graft a generic VSM supervisor or clone a fixed five-port architecture.

| Necessary native component or port | Existing file/API and evidence | Smallest proposed edit / developer integration | Legitimate owner, effect and return |
| --- | --- | --- | --- |
| Future event evaluation in Deacon | `mol-deacon-patrol` and `AgentPresetInfo` | Optional one-wisp step reading a dated trusted release signal against configured roles | Allowed decision: retain, single canary, rollback |
| Protected next-session trial | `gt sling --agent` and role config | Trigger only a new eligible session from allowed agent set; link original request to trial | Overseer envelope controls allowed presets; in-flight sessions untouched |
| Actual return to later future decision | Witness/doctor result plus Beads/mail | Join task result to wisp, send Mayor evidence and commit/revert bounded future default config | Deacon loop observes subsequent task success/failure and revises choice |

**Native-specific design advice (not a new gate):** The proposal's role-specific runtime semantics, hooks, resume, process identity, Deacon wisp, Beads and next-task routing must be preserved; a generic provider monitor with renamed roles would not supply its S4 chain.

**Architectural C-sufficiency argument:** Static preset change is an incomplete S4 chain, as is a runtime cost dashboard. Current-task intelligent routing is closer to S3 than S4. A Deacon wisp that interprets a dated release notice, chooses among explicitly permitted future alternatives, sends one new-session trial through Gas Town's existing runtime, observes its real outcome and informs the *next* role decision is a coherent optional C construction if all links can be implemented and validated. Shipped native methods supply enforcement and feedback transport, but not the prospective source→choice→future-operation→return handshake.

**Explicit non-goals:** No changing live agent sessions; no new autonomous S5 authority, no unsolicited changes to all six functions, no forced provider adaptation, no new generic VSM framework, no external GitHub publication.

**Implementation dependency graph:** P1 approved agent/role allowlist and trust limits → P1 native notice/canary/feedback-negative tests → P0 optional Deacon wisp + existing new-session selector + guarded config return → future first-party validation. P2 optional feed adapters, not a prerequisite to structural C.
